# 模板

模板是**某一类视频专用**的东西。它在通用模块之上，加入这类视频自己的内容和风格：

- 组合**组件**（`components/`），并给它们定好这类视频的参数，例如导航栏的标志和路径、转场卡片的写法；
- 加入这类视频**专属的配色和元素**，例如 GitHub 的标志、语言色点、仓库卡片、Star 按钮；方格转场在这里换成贡献图的绿色；
- 提供这类视频的**场景**（HTML），只要往里填内容就能用；
- 按场景给出**推荐的 layout**（`preferred_layouts`）与每个场景需要的真实朗读锚点。

设计主题、布局、组件对所有类型的视频都通用；模板只服务于它那一类视频。

## 现有模板

| 模板 | 视频类型 | 推荐的 layout | 场景 |
|---|---|---|---|
| `github-trending` | GitHub 热榜 / 开源项目盘点（横屏讲解模式，人物主持） | `landscape-presenter`（推荐，非门槛） | `trending-overview`（榜单总览）、`project-cover`（项目封面） |

每个模板一个目录，文档和代码放在一起：

```
templates/<类型>/
  <类型>.md          这类视频怎么组装：组件及其参数、专属配色和元素、数据怎么填、人物怎么演
  <类型>.json        机器声明：preferred_layouts（推荐性）、场景名与每个场景需要的锚点字段
  <场景>.md          每个场景的说明：参数、数据、时间、限制
  <场景>.html        场景本体：静态标记和样式，和 <场景>.mjs 一起复制到视频工程的 compositions/
  <场景>.mjs         场景的 init 入口（接口见 modules.md 的「模块初始化接口」）
  brand/ …           这类视频专属的资源（如品牌标志）
```

`<类型>.json` 是模板机器声明的唯一来源：`preferred_layouts` 是它按场景借用时
推荐的 layout（**建议性**的——执行者根据内容、画布和实际可读性判断是否适用，
不是全片硬枚举门槛）；`scenes` 列出可借用的场景部分；`anchor_fields` 声明每个
场景必须取自真实朗读文字的时间锚点。模板与场景的对应关系只写在这份声明里，
不从模板文档猜。

**模板按场景借用，不是全片锁定。** Phase 6 / 7 不选模板；Phase 8 委派的
composition agent 读 `modules/templates/templates.md`，按 [composition 基础指令第四部分](../../references/delegation/composition/base-instructions.md#四内容演绎与模板选择) 的统一规则对每个视觉场景独立判断是否借用：只在用户明确指定，或模板场景与当前 scene 的内容关系、真实朗读锚点和布局需求**特别匹配**时才采用，选中后再读 `<类型>.md`、`<类型>.json` 与对应 `<场景>.md`，并把 `{"name": "<模板>", "scene": "<场景>"}` 写进该场景的 `scene-config.json`。相邻 scene 可以一个用模板、一个自主设计；模板场景的专属配色、人物演法与导航只作用于采用它的 scene。无特别匹配时写 `template: null`，即时设计并自主实现场景，不要为了套模板改朝向、design、旁白或用户明确要求。
