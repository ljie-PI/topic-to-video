# Pattern：video-first（视频优先）

一个视频 clip 是这个 scene 的主证据：行为、演示、时间变化靠视频本身表达，文字只留短解释。本文件是建议，不是规则。

## 适用场景和触发信号

- 单个主视频，且没有命中更高优先级的特殊呈现；视频的行为 / 时间变化是主证据，文本只作短解释。
- 场景规划里 `layout_role = "video_first"`，或旁白在描述一段演示、一个动态过程。
- 近静止的视频在运动上可以按静态图片处理，但版面仍可保持 video-first。

## 区域尺寸建议

- 横屏：视频尽量接近内容区可用宽高，留少量位置给短 label / 状态说明。
- 竖屏：横视频放上半屏或中上部的清晰 slab；竖视频可接近全幅。
- 复杂结构性的信息（表格、流程图等）建议拆到相邻 scene，不要压在视频上。

## 横屏摆法

- 视频主体优先，占据内容区大部分面积；文本控制为短标签、关键数字或一句短结论。
- 文字与视频的比例失衡时，优先减文字而不是缩小视频。

## 竖屏摆法

- 横视频：上部或中上部的 wide media slab，下面接解释区。
- 也可做安全的近全幅背景，前景只放极少量 shrink-to-fit 的短 overlay。
- overlay 只放短标签 / 状态 / 时间点 callout，不放长段文字。

## 动效候选与应避免

候选：视频承担主要运动，辅以短 label、状态变化、局部 emphasis；视频本身的播放、缩放、滚动就是节奏。

避免：叠加长段 overlay 或持续文字条盖住主体；为视频再套一层与语义无关的装饰动效；把近静止视频当动态素材滥用运动。

## 用色

- 外观全部来自所选主题的 token；overlay 文字用 `--c-chrome-ink`（深底）或 `--c-ink`（浅底），保证与视频画面有足够对比。
- 状态 label 用真实语义色（`--c-info` / `--c-warning` / `--c-danger`），不做装饰性换色。
- 本 pattern 没有按 visual_role 的特殊覆盖。
