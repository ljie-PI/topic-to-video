# 布局：竖屏讲解模式（portrait-presenter）

通用带主持人竖屏布局：顶部 88px 深色导航栏，往下是全宽页眉与主展示区，主展示区下方左侧是副展示区、右侧坐主持人，底部为全宽深色双行字幕条。

**所有区域的位置和尺寸都是固定的**。模板和组件只往区域里填内容，不移动、不缩放区域本身。内容放不下时，在区域内部 zoom-in、滚动或分页。

含两种画布变体：**1080×1920（9:16）** → `portrait-presenter.json`，**1080×1440（3:4）** → `portrait-3x4-presenter.json`（数值与本文区域表严格一致）。

各区域间距（两种竖屏画布通用）：
- 导航栏下沿到页眉 32px（88 → 120 / 90，3:4 的页眉本来就压在 90）；
- 页眉底到主展示区 40px；
- 主展示区底到副展示区 40px；
- 副展示区底到字幕条 24px（9:16 的 `y = 1752`、3:4 的 `y = 1272`）；
- 副展示区右缘到人物区左缘 40px（680 → 720、720 → 760）；
- 人物区右缘距画布右边界 60px（1020 → 1080）；
- 人物区底边与字幕条上沿对齐（1476 + 300 = 1776、1036 + 260 = 1296）。

## 层级（z-index）

| 层 | z-index | 内容 |
|---|---|---|
| 背景 | — | `#ground`，在根节点最底层 |
| 场景 | 2 | 各视觉场景挂载点，按时间先后排在同一轨 |
| 转场 | 10 | 转场 `tile-wipe`（`transitions/tile-wipe/`），盖住场景，从导航栏、字幕条和人物下面穿过 |
| 导航栏 | 15 | 组件 `nav-bar`，盖住画面上沿 |
| 字幕 | 16 | 组件 `caption-bar` |
| 人物 | 20 | 组件 `presenter`，永远在最上面 |

## 挂载规则

- **常驻组件**（导航栏、字幕条、人物）各挂一次，`data-start="0"`，时长等于整支视频，宿主 `data-width` / `data-height` 对应全片竖屏画布（`1080×1920` 或 `1080×1440`）；采用转场时，常驻转场挂一次，`data-start="0"`，时长等于整支视频。它们的数据用的是视频时间（秒）。
- 导航栏用紧凑模式：`{"mode": "compact", "height": 88, "padX": 70, "logoSize": 34, "logo": "assets/brand/…", "path": "github / trending"}`，数据仍是 `VIDEO.tabs`（`[{label, at}]`）。竖屏不再画标签行，右侧显示 `NN / 总章数 · 当前章节`，底边 6px 进度线按 `t / 时长` 匀速填充；参数与行为见 [nav-bar 文档](../components/nav-bar/nav-bar.md)。`z-index: 15`。
- 人物区几何由 `scene-config` 里 `person` 区原样写进 `VIDEO.presenter.placements`（`x` / `y` / `size` 取 `rect.x` / `rect.y` / `rect.width`），不要另估坐标。
- 同片混用无主持人竖屏场景（`portrait` / `portrait-3x4`）时，不重挂组件，也不要给 `caption-bar` 传 `bar: "off"`：通过 `VIDEO.presenter.placements` 切换人物显隐与几何，通过 `VIDEO.captionSegments`（含 `caption_bar_rect`）自动切换底部字幕条显隐与双行文字区宽度。**导航栏没有按 scene 切换的能力**：混用无导航栏的 `portrait` 场景时不要挂导航栏（整片只用带导航栏的 presenter 布局，或整片不挂）。
- 采用方格转场 `tile-wipe` 时，按 [tile-wipe 文档](../transitions/tile-wipe/tile-wipe.md) 的参数公式传入本布局边界与笔记本起点（人物舞台左上角 + 0.5 倍边长、+ 0.775 倍边长）：`9:16` 为 `{"originX": 870, "originY": 1709, "top": 88, "bottom": 1776}`，`3:4` 为 `{"originX": 890, "originY": 1238, "top": 88, "bottom": 1296}`；竖屏 1080px 宽度下默认省略转场预告卡片（只做纯方格过渡），避免横屏宽卡片横向越界。

## 人物和竖屏区域的配合

人物区在画面右下角，底边停在字幕条上沿：主展示区落在人物的正上方偏左，副展示区落在人物正左侧，字幕条在人物下方全宽。

- `size`：`9:16` 为 `300`（约等于横屏讲解模式 420px 在 1080 宽画布上的等比大小），`3:4` 为 `260`；人物缩到 `300` / `260` 时，思考气泡和“!”的 `fxScale` 分别取 `1.4` / `1.6`，气泡文字稳定在约 13px，读得清且不压住副展示区。
- 视线方向（`glances`）：讲主展示区用 `U`（人抬头向上看），讲副展示区用 `L`（人向左看），主展示区偏左的具体元素也可以叠 `L`；其余规则见 [presenter 组件文档](../components/presenter/presenter.md)。
- 字幕占满 940px 内容宽度（文字框 ≈ 条宽的 87%），按 [`caption-bar.md`](../components/caption-bar/caption-bar.md) 的规则自动居中；人物不再压条，因此字幕左右都不需要为人物让位，人物的笔记本与字幕条之间保留 0 像素（底边对齐）。

## 副展示区

- **默认只排页眉 + 主展示区（`header` + `main`），一般不放 `side`**：单个动态图示、流程拓扑或焦点素材在 `940×900`（3:4 为 `940×630`）主展示区内已经完整表达时，副展示区与人物周围保持干净留白，不为“填满格子”强行塞卡片。
- **启用 `side` 的条件与跨区互补原则**：仅当场景存在独立的大块文本 / 榜单元素（如多项目排行、对比清单、关键指标组），或只放 `header` + `main` 导致画面明显空旷时才启用 `side`；启用时 `side` 内容必须与 `main`、`header` 互补（如主区展示画面证据、副区列出独立指标），不得把 `main` 里的文案在 `side` 重复抄写一遍。
- 副展示区尺寸接近横屏讲解模式的 `640×522`，横屏的副区模板可以按本区尺寸等比复用；`side` 内部同样只允许区域内部 zoom-in、滚动或分页，不越过边界。

## 元素尺度（按本布局的区域代入）

单个图标与数字的上限是**设计主题**的规则（见 [`designs.md`](../designs/designs.md) 的「字号阶梯 / 单个元素的尺度上限」），不在这里另立一套；代入本布局的区域后，写场景时直接用这几个值：

| 元素 | 主展示区 940×900 / 940×630 | 副展示区 610×512 / 650×352 |
|---|---|---|
| 指标数字（配说明同框） | ≤ 88（说明 ≥ 36px）/ ≤ 72（≥ 30px） | ≤ 60（≥ 26px）/ ≤ 42（≥ 22px） |
| 封面核心数字（整片一次） | ≤ 104（配 ≥ 42px 的一句话）/ ≤ 84（≥ 34px） | 不放 |
| 区域主图标 / logo | ≤ 160 | ≤ 154 / ≤ 106 |
| 行内图标 | 行字号 × 0.8–0.9 | 同左 |

代入的依据：数字 `≤ min(阶梯上限, 2.5 × 同框说明字号, 区域高 × 12%)`，图标 `≤ min(区域短边 × 30%, 160px)`；两个元素都必须与名称 / 说明同框，不允许单独占满一个区域。副展示区只有 512（3:4 为 352）高，是这两条最常被破的地方。

## 竖屏摆法与信息密度

内容组织遵循 [portrait.md](portrait.md) 的「竖屏摆法与信息密度」：主展示区保持 940px 全宽上下堆叠与分时轮换，不塞左右窄栏；由于顶部预留了导航栏、底部预留了人物与双行字幕条，纵向条目数应按主展示区高度（900px / 630px）克制安排，超出时优先分页、轮换或拆场景。启用副展示区时，主区与副区各自独立成篇，主区不必为副区让出高度以外的宽度。

## 不要做

- 不要把内容画进导航栏（`y < 88`）或字幕条（`y ≥ 1776` / `1296`）：页眉从 120 / 90 开始是硬边界。
- 不要把主展示区内容向下越过底边（9:16 的 `y = 1200`、3:4 的 `y = 880`），也不要让副展示区越过 `y = 1752` / `1272`，避免压住人物或字幕条。
- 不要在人物区上方或右侧另塞窄小文字块；人物周围只保留呼吸感与思考气泡，需要更多内容时用副展示区。
- 不要用一个图标或一个大数字填满副展示区（见上节「元素尺度」）。
- 字幕不要超过 `caption.width_px`（940px）对应的显示宽度，不要超过两行。
